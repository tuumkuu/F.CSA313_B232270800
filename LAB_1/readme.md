## 2. Хийсэн ажлуудын тойм

Энэхүү лабораторийн ажлаар орчин үеийн веб автоматжуулалтын дэвшилтэт хэрэгсэл болох **Playwright** framework ашиглан функционал автомат тестүүдийг боловсруулж, туршилт хийлээ.

- **Төслийн тохиргоо:** Playwright төслийг TypeScript суурьтайгаар тохируулж, Chromium, Firefox, WebKit (Safari engine) зэрэг орчин үеийн олон browser дээр зэрэгцэн (parallel) ажиллах нөхцөлийг бүрдүүлэв.
- **Хэрэглэгчийн баталгаажуулалт:** `standard_user` нэрээр системд амжилттай нэвтрэх, гарчгийн баталгаажуулалт, лого шалгах болон цэсээр дамжуулан аюулгүй гарах (Logout) алхмуудыг гүйцэтгэв.
- **Сөрөг тохиолдлын тест (Negative testing):** Буруу нууц үг оруулсан үед гарч ирэх алдааны мэдэгдэл (`[data-test="error"]`) болон оролтын талбарын алдааны CSS хэлбэржүүлэлтийг шалгасан.
- **Нэвтэрсний дараах худалдан авалтын урсгал:** Барааг сагсанд нэмэх, сагсан дээрх тоолуур (`shopping_cart_badge`) өөрчлөгдсөнийг баталгаажуулах, Cart болон Checkout алхам руу шилжих, цуцлах болон буцах үйлдлийг туршив.
- **Playwright Codegen:** Хэрэглэгчийн бодит үйлдлийг бичиж кодонд хөрвүүлэх Codegen хэрэгслийг туршиж, үүссэн кодын шаардлагагүй үйлдлүүдийг цэгцлэн сайжруулав.
- **Тайлан ба бичлэг:** Тестийн ажиллагааны явцын видео бичлэг (`docs/video.webm`), DOM snapshot бүхий Trace Viewer архив (`docs/trace.zip`) болон бие даасан HTML тайлан (`docs/index.html`)-г үүсгэж хадгаллаа.

## 3. Ашигласан Playwright API ба функцууд

Лабораторийн ажлыг боловсруулахад дараах үндсэн Playwright API-уудыг өргөн ашиглав:

| API / Функц | Зориулалт | Кодонд ашигласан жишээ |
|---|---|---|
| `page.goto()` | Заасан URL хуудас руу шилжих | `await page.goto('https://www.saucedemo.com');` |
| `page.getByPlaceholder()` | Input талбарыг placeholder утгаар нь сонгох | `page.getByPlaceholder('Username').fill('standard_user');` |
| `page.getByRole()` | Элементийг ARIA role болон нэрээр сонгох | `page.getByRole('button', { name: 'Login' }).click();` |
| `page.getByText()` | Хэрэглэгчид харагдах текстээр элементийг сонгох | `expect(page.getByText('Products')).toBeVisible();` |
| `page.locator()` | CSS selector эсвэл `data-test` атрибутаар сонгох | `page.locator('[data-test="shopping-cart-link"]')` |
| `.fill()` | Текст оруулах талбарт утга бичих | `.fill('secret_sauce')` |
| `.click()` | Товч болон холбоос дээр дарах үйлдэл хийх | `.click()` |
| `expect()` | Тестийн үр дүн, төлөв байдлыг шалгах assertion | `await expect(page).toHaveURL(/.*inventory.html/);` |
| `.toHaveURL()` | Хуудасны одоогийн хаяг (URL) зөв эсэхийг шалгах | `await expect(page).toHaveURL('https://www.saucedemo.com/');` |
| `.toBeVisible()` | Элемент DOM дээр байхаас гадна дэлгэцэнд харагдаж байгааг шалгах | `await expect(errorContainer).toBeVisible();` |
| `.toHaveText()` | Элементийн доторх текст яг тохирч байгааг шалгах | `await expect(logoLocator).toHaveText('Swag Labs');` |
| `.toContainText()` | Элементийн доторх текст тухайн үгийг агуулж байгааг шалгах | `await expect(error).toContainText('Username and password');` |
| `.toHaveClass()` | Элементийн CSS ангилал зөв байгааг шалгах | `await expect(passwordInput).toHaveClass(/error/);` |

## 4. Яагаад XPath-аас татгалзаж орчин үеийн Locator ашигласан бэ?

Энэхүү лабораторийн ажлын хүрээнд уламжлалт XPath selector-оос зориуд татгалзаж, Playwright-ийн хэрэглэгч төвтэй (user-facing) `getByRole()`, `getByPlaceholder()`, `getByText()` болон туршилтын `data-test` selector-уудыг ашигласан.

1. **DOM бүтцийн өөрчлөлтөд тэсвэртэй байдал:** XPath нь HTML элементийн бүтэц (жишээ нь `//div[2]/form/div[1]/input`) эсвэл шаталсан байршлаас хамаардаг тул UI дизайнерууд HTML-ийн бүтэц, div-ийн дарааллыг бага зэрэг өөрчлөхөд л тестүүд ажиллахаа больдог (fragile/brittle).
2. **Хэрэглэгчийн бодит мэдрэмжтэй нийцэх байдал:** `getByRole('button', { name: 'Login' })` болон `getByPlaceholder('Username')` нь дэлгэц уншигч (screen-reader) болон бодит хэрэглэгчийн харж харьцаж буй өнцгөөр элементүүдийг сонгодог тул хүртээмжтэй (accessibility) стандартыг давхар хангадаг.
3. **Хөгжүүлэлтийн тогтвортой байдал:** `data-test` атрибут нь зөвхөн тестийн автоматжуулалтад зориулагдсан тул CSS класс болон загварын өөрчлөлтөөс үл хамааран тестийг маш тогтвортой ажиллах боломжийг олгодог.

## 5. Playwright Codegen ба өөрийн бичсэн кодын ялгаа

Playwright Codegen нь браузер дээр гараар хийсэн үйлдлийг автоматаар код болгон бичиж өгдөг хүчирхэг хэрэгсэл юм. 

Командын мөрөөс Codegen ажиллуулах:
```bash
npx playwright codegen https://www.saucedemo.com
```

### Codegen-ийн үүсгэсэн кодын жишээ:
```typescript
await page.locator('[data-test="username"]').click();
await page.locator('[data-test="username"]').fill('standard_user');
await page.locator('[data-test="password"]').click();
await page.locator('[data-test="password"]').fill('secret_sauce');
await page.locator('[data-test="login-button"]').click();
```

### Ажиглалт ба харьцуулалт:
- **Илүүдэл үйлдлүүд:** Codegen нь хэрэглэгчийн талбар луу бичихээс өмнө хийсэн санамсаргүй `click()` зэрэг шаардлагагүй үйлдлүүдийг кодонд шууд оруулдаг.
- **Assertion-ийн дутагдал:** Codegen нь зөвхөн хийгдсэн үйлдлүүдийг (action) бичдэг ба хуудасны үр дүн зөв гарсан эсэхийг баталгаажуулах `expect()` assertion-уудыг автоматаар тавьж чаддаггүй.
- **Дүгнэлт:** Codegen нь шинэ хуудасны тестийн анхны суурь араг ясыг хурдан гаргаж авахад маш их цаг хэмнэдэг боловч үүссэн кодыг заавал цэвэрлэж, шаардлагагүй үйлдлүүдийг хасаж, шаардлагатай `expect()` шалгалтуудыг гараар нэмж баяжуулах шаардлагатай.

## 6. Playwright ба Selenium-ийн харьцуулсан ажиглалт

Playwright болон Selenium нь хоёулаа UI тестийг автоматжуулах өргөн боломжтой нээлттэй эхийн (Apache 2.0 лицензтэй) хэрэгслүүд юм. Гэвч хөгжүүлэлтийн явцад дараах зарчмын давуу талууд Playwright дээр тод ажиглагдлаа:

1. **Автомат хүлээлт (Auto-waiting):** Selenium дээр элементийг гарч иртэл `WebDriverWait` болон explicit/implicit wait-ийг гараар бичих шаардлага гардаг бол Playwright нь үйлдэл хийхийн өмнө элемент бэлэн, харагдахуйц, идэвхтэй болохыг автоматаар хүлээдэг нь flakiness буюу тестийн тогтворгүй байдлыг эрс бууруулдаг.
2. **Драйверын нэгдсэн удирдлага:** Selenium-д браузер бүрийн хувилбарт тохирсон `chromedriver`, `geckodriver` гэх мэт тусдаа драйвер суулгаж, замыг нь зааж өгөх шаардлагатай байдаг бол Playwright-д `npx playwright install` ганц командаар шаардлагатай бүх браузер бүрэн суугдана.
3. **Хяналт ба дебаг (Trace Viewer):** Selenium нь алдааг илрүүлэхэд үндсэн лог болон дэлгэцийн агшин авдаг бол Playwright-ийн **Trace Viewer** нь тестийн алхам бүрийн DOM snapshot, сүлжээний хүсэлт, хугацааны дарааллыг бүрэн харуулдаг нь алдааг маш хурдан олоход үнэлж баршгүй давуу тал болдог.
4. **Туршилтын нэгдсэн систем (Built-in Test Runner):** Selenium нь тестийг ажиллуулахын тулд JUnit, TestNG, Mocha, Jest зэрэг гадны фрэймворк шаарддаг бол Playwright нь өөрийн суурилагдсан хүчирхэг Test Runner, assertion сан, тайлан үүсгэгчтэй ирдэг.
5. **Орчин үеийн архитектур:** Playwright нь Chrome DevTools Protocol болон WebSocket протоколоор дамжин браузертай шууд нэг холболтоор харьцдаг тул HTTP wire protocol ашигладаг Selenium-тэй харьцуулахад тестүүд нь мэдэгдэхүйц хурдан гүйцэтгэгддэг.

## 7. Нэмэлт даалгавар (AI өнцөг — Шинжилгээ)

Төслийн нэвтрэх хэсгийн тестийг AI туслахаар үүсгүүлж, өөрийн бичсэн кодтой харьцуулан үнэлэв:

1. **Гаргасан тестийн ялгаа:** AI-ийн санал болгосон анхны кодууд нь орчин үеийн `getByPlaceholder()` эсвэл `getByRole()` гэх мэт хүртээмжтэй locator-уудын оронд уламжлалт CSS сонгогч (`input#user-name`, `#login-button`) болон XPath ашиглах хандлагатай байв.
2. **Алдаа дутагдал:** AI-ийн код нь ихэвчлэн хуудас ачааллагдсаныг л шалгаж байсан ба сөрөг тестийн үед гарч ирэх нарийн алдааны мессежийн агуулга (`toContainText`), input-ийн алдааны ангилал (`toHaveClass(/error/)`) болон тестийн төгсгөлд цэвэрлэх үйлдэл (Logout) хийхийг орхигдуулсан байв.
3. **Засвар, сайжруулалт:** AI-аас гаргасан анхны логикийг суурь болгон ашиглаж, бүх selector-уудыг Playwright-ийн шилдэг туршлага (Best Practices)-ын дагуу semantic locator болгон өөрчилж, хуудас бүрийн assertion-уудыг нарийвчлан нэмж, тестүүдийг хараат бус (test isolation) ажилладаг болгон сайжрууллаа.

## 8. Тестүүдийг ажиллуулах заавар

### Бүх тестүүдийг бүх браузер дээр ажиллуулах:
```bash
npx playwright test
```

### Тодорхой нэг тестийг сонгон ажиллуулах:
```bash
npx playwright test -g "1. Амжилттай нэвтрэх"
```
```bash
npx playwright test -g "2. Буруу нууц үгээр нэвтрэх"
```

### Тодорхой нэг браузер дээр ажиллуулах:
```bash
# Chromium (Google Chrome хөдөлгүүр)
npx playwright test --project=chromium

# Firefox
npx playwright test --project=firefox

# WebKit (Safari хөдөлгүүр)
npx playwright test --project=webkit
```

### Тестийг UI харах горимоор ажиллуулах:
```bash
npx playwright test --headed
```

### Тестийн интерактив UI горимыг нээх:
```bash
npx playwright test --ui
```

### Тестийн HTML тайланг нээж үзэх:
```bash
npx playwright show-report
```
